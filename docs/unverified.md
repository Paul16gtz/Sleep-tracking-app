# Unverified API and tooling assumptions

No Swift compiler, Xcode or XcodeGen is available in the authoring environment. Every item below could only be checked statically and must be confirmed on the Mac or in CI.

- `project.yml`: XcodeGen is expected to exclude the `Info.plist` referenced by `INFOPLIST_FILE` from the target's resources automatically. To verify: after `xcodegen generate`, check that `SleepTracker/Info.plist` does not appear under "Copy Bundle Resources". If it does, add `excludes: ["Info.plist"]` to the `SleepTracker` source entry.
- `SleepTracker/Shared/SettingsStore.swift:17`: `_settings = Published(initialValue: SettingsStore.load(from: userDefaults))` assigns the `@Published` backing storage directly in `init`, so the `didSet { save() }` observer on `settings` does not fire while loading. To verify on the Mac: it compiles without "self used before all stored properties are initialized" or an observer-on-wrapped-property diagnostic, and `testSettingsStorePersists` passes.
- `SleepTracker/Shared/SoundEventType.swift:25-28`: SF Symbols names `zzz`, `bubble.left.fill`, `wind`, `ear.fill` must exist on iOS 17 in the installed SF Symbols set. To verify: render `Image(systemName:)` for each case in a preview and check that none shows a blank image.
- `SleepTracker/Shared/Formatters.swift:42,52,60-78`: the exact output of `DateFormatter` with `de_DE` and `EE, d. MMM yyyy` (abbreviation with or without trailing dot, e.g. "Mo., 3. Feb. 2025", "Juni" vs "Jun.") depends on the CLDR version of the iOS runtime. To verify: log `Formatters.nightDate(Date())` for several months on the simulator and device; also confirm `Formatters.csvTimestamp(Date(timeIntervalSince1970: 0))` gives `1970-01-01T00:00:00Z`.

- `SleepTracker/Analysis/LabelMapping.swift:9-14`: the candidate label strings `snoring`, `speech`, `cough`, `whispering` are unverified guesses for the names in the `SNClassifySoundRequest(classifierIdentifier: .version1)` label set (`knownClassifications`); nothing is mapped for a name that is absent. To verify: open the debug screen on the device, read the full label list, and check that `availableTypes` contains all four types; if a type is missing, add the real label name to `LabelMapping.candidates` (and extend the `testMapsOnlyKnownLabels` fixture if needed).
- `SleepTracker/Persistence/Models.swift:32-33`: `@Relationship(deleteRule: .cascade, inverse: \SoundEvent.session)` / `\EpochSample.session` is declared on the session side only; the child side is a plain `var session: SleepSession?` (default delete rule `.nullify`). To verify: the schema builds without "inverse" diagnostics, and `testDeleteSessionRemovesEventsAndClipFolder` finds no `SoundEvent` or `EpochSample` left after deleting the session (cascade); `testDeleteEventRemovesClipFile` keeps the session.
- `SleepTracker/Persistence/Models.swift:35-46,97-104,127-134`: the `@Model` initializers assign every stored property, including `events = []`, `epochs = []` and `session = nil`, although these have defaults or are optional. To verify: no macro diagnostic ("return from initializer without initializing all stored properties" or a relationship-in-init warning) and no runtime trap when creating an instance before it is inserted.
- `SleepTracker/Persistence/Models.swift:25,78`: `@Attribute(.unique) var id: UUID` must satisfy `PersistentModel`'s `Identifiable` requirement with `ID == UUID` (views use `session.id`); `EpochSample` has no `id` and relies on the default `persistentModelID`. To verify: it compiles and `NavigationLink(value: session.id)` (Task 16) gets a `UUID`.
- `SleepTracker/Persistence/SessionRepository.swift:44-45,65-66`: a new event/epoch is inserted first and then appended to `session.events` / `session.epochs` (to-many side), relying on SwiftData to set the inverse `session`. To verify: `testMarkStaleRunningSessions` (reads `session.epochs`/`session.events` after `addEpoch`/`addEvent`) passes and `event.session === session` holds after save. If appending to a to-many array with about 1000 epochs per night proves slow on the device, switch to `epoch.session = session` (to-one side) and re-run the tests.
- `SleepTracker/Persistence/SessionRepository.swift:88-90`: `#Predicate<SleepSession> { session in session.statusRaw == runningRaw }` compares a stored `String` with a captured local `String`. To verify: it compiles and `testMarkStaleRunningSessions` marks only the running session; the test also assumes that changes made through the fetched instances are visible through the instances returned by `createSession` (same context). Fallback if the predicate fails: fetch all sessions and filter `statusRaw == "running"` in Swift.
- `SleepTracker/Persistence/SessionRepository.swift:8`: `static let schema` lives in a `@MainActor` class and is therefore main-actor isolated (`Schema` is not known to be `Sendable`). To verify: `AppDependencies` (Task 14) references it from a main-actor context only; otherwise the compiler reports an isolation error.
- `SleepTrackerTests/SessionRepositoryTests.swift:5,14,29`: the whole test class is `@MainActor` and overrides `setUp() async throws` / `tearDown() async throws` (imported from Objective-C, no actor annotation). To verify: no "different actor isolation from nonisolated overridden declaration" error; fallback: drop the class annotation, mark each test `@MainActor` and build the container in a `@MainActor` helper.
- `SleepTracker/Persistence/FileStore.swift:60,66-69,77,106`: `setAttributes([.protectionKey: .completeUntilFirstUserAuthentication], ofItemAtPath:)` may throw or be ignored on the simulator; `prepareDirectories`, `clipDirectory(for:)` and `deleteAllClips` therefore call `applyProtection` with `try?`, only `applyProtection` itself throws. To verify on a device: `FileManager.default.attributesOfItem(atPath:)[.protectionKey]` is `completeUntilFirstUserAuthentication` for `Clips`, a session clip folder, `Store` and the store file.
- `SleepTracker/Persistence/FileStore.swift:112-129`: `clipsTotalSize()` uses `FileManager.enumerator(at:includingPropertiesForKeys:options:errorHandler:)` with `for case let url as URL` and `resourceValues(forKeys:)` (`isRegularFile`, `fileSize`); `fileSize` is the logical size, not the allocated size on disk. To verify: `testClipsTotalSizeSumsFiles` gives 30 and directories contribute nothing.

- `SleepTracker/Audio/MicrophoneAudioSource.swift:146-155`: `inputNode.installTap(onBus: 0, bufferSize: tapBufferSize, format: inputFormat, block:)` with the node's own `outputFormat(forBus: 0)`; trailing closure of type `AVAudioNodeTapBlock` = `(AVAudioPCMBuffer, AVAudioTime) -> Void`, assumed to run on a non-real-time engine thread (so allocating the mono copy there is fine). `bufferSize` is only a request; iOS often delivers about 100 ms (e.g. 4800 frames at 48 kHz). To verify on a device: no exception on install, buffers arrive about every 0.1 s, `frameLength > 0`, format equals `inputFormat`. Fallback if allocation in the tap shows glitches: preallocate a small pool of mono buffers.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:127-137`: `outputFormat(forBus: 0)` reports `sampleRate == 0` / `channelCount == 0` when the session is inactive or permission is missing (then `noInputFormat`). Lines 134-137 additionally compare it with `inputNode.inputFormat(forBus: 0).sampleRate` (assumed to be the hardware rate) to avoid the "format.sampleRate == hwFormat.sampleRate" exception right after a route change. To verify: in steady state both rates are equal on the device and the simulator, so `start()` succeeds. Fallback: if `start()` always fails with "Kein Mikrofon-Eingang verfügbar.", delete lines 131-137.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:158-164,337-346`: `NotificationCenter.addObserver(forName: .AVAudioEngineConfigurationChange, object: engine, queue: .main)`; the engine is assumed to stop itself and post this notification (on an arbitrary thread) when the input hardware changes. To verify: plugging and unplugging a wired headset during a night gives one or two restarts (one gap each) and no restart loop; starting a fresh engine does not post the notification by itself. Fallback if a loop occurs: ignore configuration changes for about 1 s after a segment begins.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:285-310`: interruption `userInfo[AVAudioSessionInterruptionTypeKey] as? UInt` -> `AVAudioSession.InterruptionType(rawValue:)` and `userInfo[AVAudioSessionInterruptionOptionKey] as? UInt` -> `AVAudioSession.InterruptionOptions(rawValue:)`, `.shouldResume`. As designed, `.ended` without `.shouldResume` does not restart. To verify with the screen locked: a phone call, a Clock alarm and Siri each end with `.shouldResume`, capture resumes, and exactly one gap is recorded. Fallback if `.shouldResume` is missing in one of these cases: restart on every `.ended`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:215-232`: restarting while the app is in the background with the screen locked (`setActive(true)` plus `AVAudioEngine.start()` after an interruption ended) is assumed to be allowed because of `UIBackgroundModes = [audio]`. iOS may refuse (e.g. `AVAudioSession.ErrorCode.cannotStartRecording` or `.insufficientPriority`). To verify: phone call while locked, then check that buffers flow again (live level after unlocking, gap closed). Fallback: none in this layer; the retries (immediate, then after 1, 2, 5, 10, 30 s) end in `didFailWith(MicrophoneError.restartFailed)`, which the pipeline reports.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:312-325`: `notification.userInfo?[AVAudioSessionRouteChangeReasonKey] as? UInt` -> `AVAudioSession.RouteChangeReason(rawValue:)`; only `.oldDeviceUnavailable` and `.newDeviceAvailable` restart, so the `.categoryChange` caused by our own `setCategory` does not loop. To verify: headset plug and unplug produce a restart with reason `routeChange`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:261-276`: the three session observers are registered with `object: AVAudioSession.sharedInstance()`; assumed that `mediaServicesWereResetNotification` is posted with that object too. To verify: Settings > Developer > Reset Media Services during a night records a gap with reason `mediaServicesReset` and capture resumes. Fallback: register that observer with `object: nil`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:184-200,327-335`: after a media services reset, `tearDownEngine()` still calls `removeTap(onBus: 0)` and `stop()` on the old, invalid engine; assumed to be harmless. To verify with Reset Media Services: no crash. Fallback: for `.mediaServicesReset` drop the engine reference without calling into it.
- `SleepTracker/Audio/AudioSessionManager.swift:14-15,19-20,26`: `setCategory(_:mode:options:)` (throws), `setActive(_:)` and `setActive(_:options:)` with `.notifyOthersOnDeactivation`; `try session.setActive(true)` is assumed not to be ambiguous with the `options:` overload. Fallback: `setActive(true, options: [])`.
- `SleepTracker/Audio/ClipWriter.swift:58-64`: `AVAudioFile(forWriting:settings:commonFormat: .pcmFormatFloat32, interleaved: false)` with `AVFormatIDKey: kAudioFormatMPEG4AAC` (an `AudioFormatID`/`UInt32` in `[String: Any]`), `AVSampleRateKey` = native rate, 1 channel, `AVEncoderBitRateKey: 48_000`. To verify on the device and the simulator: `open` succeeds and a clip plays. Fallback: `Int(kAudioFormatMPEG4AAC)`; if the encoder rejects 48 kbit/s at the native rate, drop `AVEncoderBitRateKey` or use `AVEncoderAudioQualityKey`.
- `SleepTracker/Audio/ClipWriter.swift:85-87`: `close()` only releases the `AVAudioFile`; the AAC file is assumed to be finalized in `deinit` (no `close()` before iOS 18). To verify: after `close()` the clip plays in full with `AVAudioPlayer` and its duration matches the written sample count. Fallback: none needed on iOS 17 as long as nothing else retains the file.
- `SleepTracker/Audio/ClipWriter.swift:74-83`: `write(from:)` gets a buffer built in `file.processingFormat` (assumed mono Float32 non-interleaved at the clip rate), not in the separately built mono format, because the buffer format must match the processing format exactly. A pre-roll of up to 10 s (480 000 frames) is written in one call. To verify: no format-mismatch error and no truncation of the pre-roll.
- `SleepTracker/Audio/ClipWriter.swift:67-69`: `applyProtection(to:)` is called with `try?` right after `AVAudioFile` init, assuming the file already exists then and inherits the clip folder's protection class otherwise. To verify on a device: `FileManager.default.attributesOfItem(atPath:)[.protectionKey]` of a clip is `completeUntilFirstUserAuthentication`.
- `SleepTracker/Audio/MonoDownmix.swift:29,61,83`: `AVAudioPCMBuffer.stride` is assumed to be 1 for non-interleaved and `channelCount` for interleaved buffers, and for interleaved data only `floatChannelData[0]` is valid. To verify: test mode (Task 23) with a stereo file gives the same levels as the mono version of that file.
