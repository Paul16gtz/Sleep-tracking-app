# Unverified API and tooling assumptions

No Swift compiler, Xcode or XcodeGen is available in the authoring environment. Every item below could only be checked statically and must be confirmed on the Mac or in CI.

- `project.yml`: XcodeGen is expected to exclude the `Info.plist` referenced by `INFOPLIST_FILE` from the target's resources automatically. To verify: after `xcodegen generate`, check that `SleepTracker/Info.plist` does not appear under "Copy Bundle Resources". If it does, add `excludes: ["Info.plist"]` to the `SleepTracker` source entry.
- `SleepTracker/Shared/SettingsStore.swift:17`: `_settings = Published(initialValue: SettingsStore.load(from: userDefaults))` assigns the `@Published` backing storage directly in `init`, so the `didSet { save() }` observer on `settings` does not fire while loading. To verify on the Mac: it compiles without "self used before all stored properties are initialized" or an observer-on-wrapped-property diagnostic, and `testSettingsStorePersists` passes.
- `SleepTracker/Shared/SoundEventType.swift:25-28`: SF Symbols names `zzz`, `bubble.left.fill`, `wind`, `ear.fill` must exist on iOS 17 in the installed SF Symbols set. To verify: render `Image(systemName:)` for each case in a preview and check that none shows a blank image.
- `SleepTracker/Shared/Formatters.swift:42,52,60-78`: the exact output of `DateFormatter` with `de_DE` and `EE, d. MMM yyyy` (abbreviation with or without trailing dot, e.g. "Mo., 3. Feb. 2025", "Juni" vs "Jun.") depends on the CLDR version of the iOS runtime. To verify: log `Formatters.nightDate(Date())` for several months on the simulator and device; also confirm `Formatters.csvTimestamp(Date(timeIntervalSince1970: 0))` gives `1970-01-01T00:00:00Z`.

- `SleepTracker/Analysis/LabelMapping.swift:9-14`: the candidate label strings `snoring`, `speech`, `cough`, `whispering` are unverified guesses for the names in the `SNClassifySoundRequest(classifierIdentifier: .version1)` label set (`knownClassifications`); nothing is mapped for a name that is absent. To verify: open the debug screen on the device, read the full label list, and check that `availableTypes` contains all four types; if a type is missing, add the real label name to `LabelMapping.candidates` (and extend the `testMapsOnlyKnownLabels` fixture if needed).
- `SleepTracker/Persistence/Models.swift:32-33`: `@Relationship(deleteRule: .cascade, inverse: \SoundEvent.session)` / `\EpochSample.session` is declared on the session side only; the child side is a plain `var session: SleepSession?` (default delete rule `.nullify`). To verify: the schema builds without "inverse" diagnostics, and `testDeleteSessionRemovesEventsAndClipFolder` finds no `SoundEvent` or `EpochSample` left after deleting the session (cascade); `testDeleteEventRemovesClipFile` keeps the session.
- `SleepTracker/Persistence/Models.swift:35-46,97-104,127-134`: the `@Model` initializers assign every stored property, including `events = []`, `epochs = []` and `session = nil`, although these have defaults or are optional. To verify: no macro diagnostic ("return from initializer without initializing all stored properties" or a relationship-in-init warning) and no runtime trap when creating an instance before it is inserted.
- `SleepTracker/Persistence/Models.swift:25,78`: `@Attribute(.unique) var id: UUID` must satisfy `PersistentModel`'s `Identifiable` requirement with `ID == UUID` (views use `session.id`); `EpochSample` has no `id` and relies on the default `persistentModelID`. To verify: it compiles and `NavigationLink(value: session.id)` (Task 16) gets a `UUID`.
- `SleepTracker/Persistence/SessionRepository.swift:44-45,65-66`: a new event/epoch is inserted first and then appended to `session.events` / `session.epochs` (to-many side), relying on SwiftData to set the inverse `session`. To verify: `testMarkStaleRunningSessions` (reads `session.epochs`/`session.events` after `addEpoch`/`addEvent`) passes and `event.session === session` holds after save. If appending to a to-many array with about 1000 epochs per night proves slow on the device, switch to `epoch.session = session` (to-one side) and re-run the tests.
- `SleepTracker/Persistence/SessionRepository.swift:88-90`: `#Predicate<SleepSession> { session in session.statusRaw == runningRaw }` compares a stored `String` with a captured local `String`. To verify: it compiles and `testMarkStaleRunningSessions` marks only the running session; the test also assumes that changes made through the fetched instances are visible through the instances returned by `createSession` (same context). Fallback if the predicate fails: fetch all sessions and filter `statusRaw == "running"` in Swift.
- `SleepTracker/Persistence/SessionRepository.swift:8`: `static let schema` lives in a `@MainActor` class and is therefore main-actor isolated (`Schema` is not known to be `Sendable`). To verify: `AppDependencies` (Task 14) references it from a main-actor context only; otherwise the compiler reports an isolation error.
- `SleepTrackerTests/SessionRepositoryTests.swift:5,14,29`: the whole test class is `@MainActor` and overrides `setUp() async throws` / `tearDown() async throws` (imported from Objective-C, no actor annotation). To verify: no "different actor isolation from nonisolated overridden declaration" error; fallback: drop the class annotation, mark each test `@MainActor` and build the container in a `@MainActor` helper.
- `SleepTracker/Persistence/FileStore.swift:60,66-69,77,106`: `setAttributes([.protectionKey: .completeUntilFirstUserAuthentication], ofItemAtPath:)` may throw or be ignored on the simulator; `prepareDirectories`, `clipDirectory(for:)` and `deleteAllClips` therefore call `applyProtection` with `try?`, only `applyProtection` itself throws. To verify on a device: `FileManager.default.attributesOfItem(atPath:)[.protectionKey]` is `completeUntilFirstUserAuthentication` for `Clips`, a session clip folder, `Store` and the store file.
- `SleepTracker/Persistence/FileStore.swift:112-129`: `clipsTotalSize()` uses `FileManager.enumerator(at:includingPropertiesForKeys:options:errorHandler:)` with `for case let url as URL` and `resourceValues(forKeys:)` (`isRegularFile`, `fileSize`); `fileSize` is the logical size, not the allocated size on disk. To verify: `testClipsTotalSizeSumsFiles` gives 30 and directories contribute nothing.

- `SleepTracker/Audio/MicrophoneAudioSource.swift:168-177`: `inputNode.installTap(onBus: 0, bufferSize: tapBufferSize, format: inputFormat, block:)` with the node's own `outputFormat(forBus: 0)`; trailing closure of type `AVAudioNodeTapBlock` = `(AVAudioPCMBuffer, AVAudioTime) -> Void`, assumed to run on a non-real-time engine thread (so allocating the mono copy there is fine). `bufferSize` is only a request; iOS often delivers about 100 ms (e.g. 4800 frames at 48 kHz). To verify on a device: no exception on install, buffers arrive about every 0.1 s, `frameLength > 0`, format equals `inputFormat`. Fallback if allocation in the tap shows glitches: preallocate a small pool of mono buffers.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:149-159`: `outputFormat(forBus: 0)` reports `sampleRate == 0` / `channelCount == 0` when the session is inactive or permission is missing (then `noInputFormat`). Lines 156-159 additionally compare it with `inputNode.inputFormat(forBus: 0).sampleRate` (assumed to be the hardware rate) to avoid the "format.sampleRate == hwFormat.sampleRate" exception right after a route change. To verify: in steady state both rates are equal on the device and the simulator, so `start()` succeeds. Fallback: if `start()` always fails with "Kein Mikrofon-Eingang verfügbar.", delete lines 153-159.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:180-186,403-412`: `NotificationCenter.addObserver(forName: .AVAudioEngineConfigurationChange, object: engine, queue: .main)`; the engine is assumed to stop itself and post this notification (on an arbitrary thread) when the input hardware changes. To verify: plugging and unplugging a wired headset during a night gives one or two restarts (one gap each) and no restart loop; starting a fresh engine does not post the notification by itself. Fallback if a loop occurs: ignore configuration changes for about 1 s after a segment begins.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:351-376`: interruption `userInfo[AVAudioSessionInterruptionTypeKey] as? UInt` -> `AVAudioSession.InterruptionType(rawValue:)`. Every `.ended` restarts capture, with or without `.shouldResume`; if another app still holds the session, the activation fails and the retry chain takes over. A `.ended` without a preceding `.began` causes one unnecessary restart (a short gap). To verify with the screen locked: after a phone call, a Clock alarm and Siri, capture resumes and exactly one gap is recorded. Also check that iOS delivers `.ended` to the app at all after an interruption longer than 30 s (for example a 2-minute call while locked), because the app may be suspended while it neither records nor holds a background task. Fallback if `.ended` is not delivered: none in this layer; the gap stays open until `stop()`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:241-262`: restarting while the app is in the background with the screen locked (`setActive(true)` plus `AVAudioEngine.start()` after an interruption ended) is assumed to be allowed because of `UIBackgroundModes = [audio]`. iOS may refuse (for example `AVAudioSession.ErrorCode.cannotStartRecording` or `.insufficientPriority`). While retries are pending the app neither records nor plays, so a background task assertion (lines 298-323) keeps it running from the first failed attempt until success, the final failure, `.began` or `stop()`. About 30 s of background time cover the retries after 1, 2, 5 and 10 s (18 s in total) but not the one after 30 s. When the assertion expires, `didFailWith(MicrophoneError.restartFailed)` is reported at once and the 30 s retry only runs if the app gets CPU time again. `didFailWith` reaching the delegate before the app is suspended is therefore not guaranteed; it may arrive only when the app runs again. To verify: phone call while locked, then check that buffers flow again (live level after unlocking, gap closed). Also force a failing restart in the background (for example temporarily throw in `beginSegment`) and check in the console that the retries run and that `didFailWith` arrives.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:378-391`: `notification.userInfo?[AVAudioSessionRouteChangeReasonKey] as? UInt` -> `AVAudioSession.RouteChangeReason(rawValue:)`; only `.oldDeviceUnavailable` and `.newDeviceAvailable` restart, so the `.categoryChange` caused by our own `setCategory` does not loop. To verify: headset plug and unplug produce a restart with reason `routeChange`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:327-342`: the three session observers are registered with `object: AVAudioSession.sharedInstance()`; assumed that `mediaServicesWereResetNotification` is posted with that object too. To verify: Settings > Developer > Reset Media Services during a night records a gap with reason `mediaServicesReset` and capture resumes. Fallback: register that observer with `object: nil`.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:207-224,393-401`: after a media services reset, `tearDownEngine()` still calls `removeTap(onBus: 0)` and `stop()` on the old, invalid engine; assumed to be harmless. To verify with Reset Media Services: no crash. Fallback: for `.mediaServicesReset` drop the engine reference without calling into it.
- `SleepTracker/Audio/AudioSessionManager.swift:14-15,19-20,26`: `setCategory(_:mode:options:)` (throws), `setActive(_:)` and `setActive(_:options:)` with `.notifyOthersOnDeactivation`; `try session.setActive(true)` is assumed not to be ambiguous with the `options:` overload. Fallback: `setActive(true, options: [])`.
- `SleepTracker/Audio/ClipWriter.swift:58-64`: `AVAudioFile(forWriting:settings:commonFormat: .pcmFormatFloat32, interleaved: false)` with `AVFormatIDKey: kAudioFormatMPEG4AAC` (an `AudioFormatID`/`UInt32` in `[String: Any]`), `AVSampleRateKey` = native rate, 1 channel, `AVEncoderBitRateKey: 48_000`. To verify on the device and the simulator: `open` succeeds and a clip plays. Fallback: `Int(kAudioFormatMPEG4AAC)`; if the encoder rejects 48 kbit/s at the native rate, drop `AVEncoderBitRateKey` or use `AVEncoderAudioQualityKey`.
- `SleepTracker/Audio/ClipWriter.swift:85-87`: `close()` only releases the `AVAudioFile`; the AAC file is assumed to be finalized in `deinit` (no `close()` before iOS 18). To verify: after `close()` the clip plays in full with `AVAudioPlayer` and its duration matches the written sample count. Fallback: none needed on iOS 17 as long as nothing else retains the file.
- `SleepTracker/Audio/ClipWriter.swift:74-83`: `write(from:)` gets a buffer built in `file.processingFormat` (assumed mono Float32 non-interleaved at the clip rate), not in the separately built mono format, because the buffer format must match the processing format exactly. A pre-roll of up to 10 s (480 000 frames) is written in one call. To verify: no format-mismatch error and no truncation of the pre-roll.
- `SleepTracker/Audio/ClipWriter.swift:67-69`: `applyProtection(to:)` is called with `try?` right after `AVAudioFile` init, assuming the file already exists then and inherits the clip folder's protection class otherwise. To verify on a device: `FileManager.default.attributesOfItem(atPath:)[.protectionKey]` of a clip is `completeUntilFirstUserAuthentication`.
- `SleepTracker/Audio/MonoDownmix.swift:29,61,83`: `AVAudioPCMBuffer.stride` is assumed to be 1 for non-interleaved and `channelCount` for interleaved buffers, and for interleaved data only `floatChannelData[0]` is valid. To verify: test mode (Task 23) with a stereo file gives the same levels as the mono version of that file.

- `SleepTracker/Analysis/SoundClassifierService.swift:42,63`: `SNClassifySoundRequest(classifierIdentifier: .version1)` is a throwing init (iOS 15+) taking `SNClassifierIdentifier.version1`; `knownClassifications` is assumed to be `[String]` with exactly that property name. To verify: it compiles, and the Debug screen shows the full label list (a few hundred entries) from `SoundClassifierService.knownLabels()`.
- `SleepTracker/Analysis/SoundClassifierService.swift:43-51,74-84`: `windowDuration` is assumed to be a settable `CMTime`, and `windowDurationConstraint` is assumed to be the Swift overlay enum `enum SNTimeDurationConstraint { case enumeratedDurations([CMTime]); case durationRange(CMTimeRange) }`. Only `.enumeratedDurations` is matched (`guard case`): the duration closest to 1.5 s is taken; in every other case 1.5 s is set directly. `.version1` is expected to allow a range of about 0.5-15 s, so 1.5 s should be valid. Assigning a value outside the constraint is assumed not to be reported as a Swift error (possibly an Objective-C exception). To verify on the device: log `request.windowDurationConstraint` and `effectiveWindowDuration` (lines 34-36) after init; results then have `timeRange.duration.seconds` of about 1.5. Fallback if the `guard case .enumeratedDurations(let durations)` pattern does not compile (other enum shape, or the constraint is imported as the Objective-C class with `type`/`enumeratedDurations: [NSValue]`/`durationRange: CMTimeRange`): delete `allowedWindowDuration` and its call and set `request.windowDuration = CMTime(seconds: SoundClassifierService.windowDuration, preferredTimescale: 48_000)` directly. If 1.5 s turns out not to be allowed, record the effective duration in the README (detection latency of N = 2 windows changes, spec B7).
- `SleepTracker/Analysis/SoundClassifierService.swift:52`: `overlapFactor` is a settable `Double` and 0.5 is accepted, giving one result every 0.75 s. To verify: consecutive results' `timeRange.start.seconds` differ by about 0.75.
- `SleepTracker/Analysis/SoundClassifierService.swift:10-15,98-112` (result-delivery thread): `SNAudioStreamAnalyzer` is assumed to call `request(_:didProduce:)`, `request(_:didFailWithError:)` and `requestDidComplete(_:)` synchronously on the thread that calls `analyze(_:atAudioFramePosition:)` / `completeAnalysis()`, i.e. the pipeline's serial analysis queue, and `completeAnalysis()` is assumed to deliver the final results before it returns (the pipeline releases the classifier right after it). To verify: temporarily add `dispatchPrecondition(condition: .onQueue(pipeline.queue))` in the pipeline's `classifier(_:didProduce:topLabels:)` and run a night on the device and test mode. Fallback if results arrive on an internal SoundAnalysis queue: pass the analysis queue into the factory and hop with `queue.async` in `request(_:didProduce:)` before calling the delegate (otherwise pipeline state races).
- `SleepTracker/Analysis/SoundClassifierService.swift:54,58`: `SNAudioStreamAnalyzer(format:)` is non-failable and accepts the mono Float32 non-interleaved processing format at the native sample rate (48 kHz or 44.1 kHz; resampled internally); `add(_:withObserver:)` throws and is assumed to hold the observer weakly, so service -> analyzer -> service is no retain cycle. To verify: no `didFailWithError` at start on the device and with a 44.1 kHz test file; the memory graph shows no leaked `SoundClassifierService` after several restarts (interruptions). Fallback if the observer is retained strongly: call `analyzer.removeAllRequests()` after `analyzer.completeAnalysis()` in `completeAnalysis()`.
- `SleepTracker/Analysis/SoundClassifierService.swift:89,102-103`: `analyze(_:atAudioFramePosition:)` (`AVAudioBuffer`, `AVAudioFramePosition`) is assumed to derive `SNClassificationResult.timeRange` from the passed frame positions in the time base of the analyzer's format, with frame 0 at `CMTime` zero, so `timeOffset + timeRange.start.seconds` is seconds since session start. To verify in test mode (Task 23): a file with a known sound at second t gives a window starting near t; after an interruption the first window of the new segment starts near the new segment base.
- `SleepTracker/Analysis/SoundClassifierService.swift:100-108`: `SNRequest`/`SNResult` are used as plain protocol types (Swift 5, no `any`), `SNClassificationResult.classifications` is `[SNClassification]` with `identifier: String` and `confidence: Double`. To verify: it compiles; the Debug screen shows top-5 labels with confidences between 0 and 1.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:207-224,55-59`: an engine removed by a teardown is kept in `retiredEngine` and released only at the next teardown or in `deinit`, never inside its own `AVAudioEngineConfigurationChange` handler (the AVAudioEngine.h note says deallocating the engine there can deadlock). This assumes that by the next teardown the notification that triggered the restart has been released by its poster. An engine whose `start()` fails in `beginSegment` is released when that function returns, possibly inside the handler of the previous engine; this is assumed to be safe because it is a different engine. To verify: plug and unplug a wired headset about ten times during a night run; there is no hang on the main thread and each change records one gap.
- `SleepTracker/Audio/MicrophoneAudioSource.swift:94-107,298-323`: `UIApplication.shared.beginBackgroundTask(withName:expirationHandler:) -> UIBackgroundTaskIdentifier`, `endBackgroundTask(_:)` and `UIBackgroundTaskIdentifier.invalid` are called from this nonisolated, non-`@MainActor` class (always on the main thread, except possibly in `deinit`). It is assumed that Swift 5 mode with `SWIFT_STRICT_CONCURRENCY = minimal` gives no error for these `@MainActor` UIKit APIs, that the expiration handler runs on the main thread, and that `endBackgroundTask(_:)` may be called from `deinit` on another thread. Fallback: wrap the main-thread calls in `MainActor.assumeIsolated { ... }` (iOS 17), and in `deinit` capture the identifier and end it with `DispatchQueue.main.async`.
